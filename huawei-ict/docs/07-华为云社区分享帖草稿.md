## 标题

用华为云 AgentArts 做一个“看得见证据”的课程学习多智能体｜知径 EduPath 实践

## 摘要

我们把“学习画像—课程证据—资源生成—练习评估—路径调整”做成了一个可执行的 Agent 闭环：主控 + 7 个角色智能体，12 节点工作流，10 个 MCP 工具，课程知识库接入 AgentArts。学生只说一句话，系统会先读画像、再找证据、再生成讲义/导图/练习，最后用测验结果反过来调整路径。所有结论都能点回课程 chunk，质量与安全双门禁不通过就不发布。

---

## 一、为什么做这件事

高校专业基础课有一个很具体的矛盾：

- 一个班几十到上百人，老师只能按“平均进度”讲；
- 学生知道自己“没学好”，但说不清弱在哪、下一步该学什么；
- 通用 AI 能生成很多内容，但常常脱离教材、无法核验，学生越用越不敢信；
- 题库/刷题 App 有题，但题目和“我当前的薄弱点”没关系，练完也没有反馈。

我们想做的不是“又一个 AI 问答”，而是一个**能解释自己为什么这样教**的学习系统。

## 二、方案：一条可执行的学习闭环

```text
学生一句话
  → 画像 Agent：目标/薄弱点/偏好/时间预算（带版本与更新理由）
  → 检索 Agent：课程知识库取证（来源/许可证/分数）
  → 教学设计 Agent：选资源类型、难度、顺序
  → 生成 Agent：讲义 / 导图 / 题库 / 代码实验（每条结论带引用）
  → 评估 Agent：五维质量门禁
  → 安全 Agent：学术诚信/隐私/事实性/价值观
  → 路径 Agent：3 天任务 + 测验后重规划
```

关键不是“角色多”，而是**每个角色可以独立重试、独立评测、独立换模型**。比如检索 0 命中时，系统会拒答，而不是让模型编一段。

## 三、为什么选 AgentArts

我们对比过“自己写编排”和“平台编排”：

| 维度 | 自写 Python 编排 | AgentArts |
| --- | --- | --- |
| 智能体/工作流 | 代码即配置，改一次要发版 | 画布配置，改完即试运行 |
| 知识库 | 自己维护 Chroma/分段/引用 | 平台知识库 + pangu_embedding/rerank + 引用 |
| 工具 | 内部 HTTP，平台看不见 | MCP 自动发现，工具调用可追踪 |
| 发布 | 自己写 API/鉴权/网关 | 平台发布 API/Web |
| 评测 | 自己写脚本 | 平台评测集 + 运行记录 |

我们用**旁路适配**的方式接入：原项目的 RAG、生成、评估能力不动，通过 MCP 暴露成 10 个工具；AgentArts 负责编排、知识、发布与评测。这样既不推翻已有工程，又能拿到平台能力。

## 四、平台里具体做了什么

### 4.1 知识库

- 2 门课、108 篇公开语料（cp-algorithms / OpenDSA / RISC-V / Ibex），保留 commit、许可证、归属。
- 自动分段，标题层级 3，约 500 字；`pangu_embedding` + `pangu_rerank`。
- 命中测试：强命中 3 条 + 弱命中 1 条（弱命中用于验证“该拒答时拒答”）。

### 4.2 工作流

12 个节点：意图识别 → 课程确认 → 画像/检索并行 → 资源规划 → 三路并行生成 → 质量门禁 → 安全审核 → 发布 → 路径规划 → 结束。测验分支走“评估 → 重规划”。

### 4.3 MCP 工具

10 个：画像、检索、资源规划、资源生成、路径、辅导、出题、测验分析、安全审核、课程大纲。

```bash
python -m bridge.mcp_server --list-tools
```

### 4.4 发布与评测

- 提交版本并记录版本号；
- 发布 API/Web；
- 24 条评测集：正常任务、弱证据、学术诚信风险、空输入、跨课程、多轮追问；
- 指标：任务成功率、证据覆盖率、引用可追溯率、安全拦截率、P95 时延。

## 五、效果：我们只说自己验证过的

**工程验证（原项目公开记录）**：

- AI 服务 82 项测试、Java 56 项、前端 29 项断言、2 项 Chromium E2E 通过；
- 真实 HTTP 学习闭环 5 个任务成功，三类资源落库，画像/路径版本 1→2；
- 知识库生命周期：上传→检索→重建→拒绝→删除；
- GitHub CI 三组通过。

**这次 Demo 的链路**：

- 9 步 Agent 轨迹、5 条课程证据、3 类资源；
- 质量门禁 88/100（A），安全审核 4 项通过；
- 3 天路径，测验后可插入补救任务。

**我们不宣称**：

- 不宣称“提升学习成绩”——没有做对照实验；
- 不宣称“全学科通用”——目前 2 门课；
- 不宣称“完全自动批改”——分数由业务系统确定性计算，AI 只做解释。

## 六、踩过的坑

1. **平台知识库不对外提供检索 API**：高代码 Agent 不能直接调；要么用平台内智能体，要么实现第三方知识库接口给平台调。我们选了前者，MCP 检索作为补充。
2. **弱命中必须自己卡阈值**：服务端可能返回全部切片，0.05 分也在里面；阈值要在工作流/应用侧做。
3. **“多智能体”不是越多越好**：平台没有强制的 handoff 原语；我们把角色拆成工作流节点，保证可观测、可重试，而不是追求“8 个独立运行时”。
4. **引用要校验**：模型会写 `[E1]`，但 E1 不一定在检索结果里；发布前必须校验，否则降级草稿。
