# 08 · 评审得分策略与答辩要点

> 用途：初赛材料自检、决赛路演、团队内部对齐口径。
> 核心：**创新性 60% 靠“场景 + 交互 + 架构”的组合差异；应用价值 40% 靠“真实需求 + 可复制 + 可验证”。**

## 3. 高频问题与回答

### Q1：你们和通用 AI 学习助手有什么区别？

**答**：三个不同。第一，内容必须引用课程 chunk，弱证据拒答；第二，画像带版本，测验结果会改画像和路径；第三，质量/安全双门禁，不通过不发布。通用助手通常是一次性问答。

### Q2：这不就是 RAG + Prompt 吗？

**答**：RAG 只是其中一步。我们还有画像抽取、资源规划、多资源并行生成、五维质量门禁、四类安全审核、路径重规划、任务状态与失败降级。RAG 解决“有没有依据”，我们解决“教什么、怎么教、教完怎么调”。

### Q3：为什么用多 Agent？单 Agent 不能做吗？

**答**：可以，官方也明确不强制多智能体。我们拆开是因为职责和失败边界不同：检索失败要拒答，生成失败要重试，评估失败要降级，安全失败要拦截。拆开才能独立评测和替换模型。不是为了多而多。

### Q4：平台知识库和你们原来的 Chroma 是什么关系？

**答**：两条通路。平台内工作流用平台知识库，引用和命中测试开箱即用；高代码/原有 RAG 通过 MCP 工具提供检索。平台知识库目前不对外提供检索 API，所以我们没有宣称“高代码 Agent 直接调平台知识库”。

### Q5：你们真的在 AgentArts 上构建了吗？

**答**：是。知识库、工作流、MCP 工具、版本、发布、评测都在平台内；我们有版本号和运行截图。原项目代码零改动，通过 MCP 复用。您可以在 Demo 右上角看到运行模式。

### Q6：数据/效果怎么证明？

**答**：工程验证有 82 项 AI 测试、56 项 Java、29 项前端断言、2 项 E2E、真实 HTTP 五任务闭环；这次 Demo 有 9 步轨迹、5 条证据、88 分质量门禁。学习效果我们没有对照实验，不宣称提分；下一步做班级试点。

### Q7：商业化怎么落地？

**答**：三种交付：① 课程包（给院系/课程团队）；② 教师工作台（备课/分层/班级洞察）；③ SaaS 订阅（按课程/班级）。复制成本主要是语料授权与知识点整理，工作流和工具复用。

### Q8：知识库版权/学生隐私怎么处理？

**答**：只用有许可证的公开语料（MIT/CC BY-SA/CC BY/Apache），保留 commit 与归属；演示用脱敏画像，不接真实学号姓名；教师数据聚合使用。安全员拦截代写/代考与隐私泄露。

### Q9：如果知识库没有相关内容怎么办？

**答**：拒答。检索分数低于阈值时，明确说“现有资料未覆盖”，建议换知识点或问教师；不让模型用通用知识补。这是我们的“负例”设计。

### Q10：质量分 88 是谁打的？会不会自说自话？

**答**：五维规则 + 模型评审的组合，权重和门禁在代码里；它用于“发布前拦截”，不是学术评价。我们也在平台评测集上跑任务成功率/引用可追溯率，两个口径分开。

### Q11：为什么先做这两门课？

**答**：专业基础课，知识点结构清晰、公开语料质量高、学生痛点集中；适合验证“证据约束 + 路径闭环”。复制到其他课需要合法语料和知识点整理，不是零成本。

### Q12：团队分工？

**答**：（按实际填写）前端/UI、AI 编排与 RAG、后端与部署、课程语料与评测。不要说“一个人全栈”，评委可能追问细节。

## 6. 答辩“不要做”

- 不要念 PPT；用 Demo 说话。
- 不要说“平台强制多智能体”。
- 不要说“平台知识库可以被任意 Agent 调用”。
- 不要说“提升了学习成绩/学习效率 X%”。
- 不要把 fixture 演示说成真实模型运行。
- 不要贬低其他队伍/开源项目；讲自己的取舍。
- 不要承诺“马上全学科通用”。

---

## 7. 答辩“要做”

- 先讲一个学生故事，再讲架构。
- 主动展示“弱证据拒答”和“风险拦截”，比多讲一个功能加分。
- 主动说边界：2 门课、无学习效果实验、平台版本可能变化。
- 每个数字都带来源（仓库/截图/日志）。
- 留一张“一页纸”给评委：架构图 + 3 个数字 + 二维码/链接。
