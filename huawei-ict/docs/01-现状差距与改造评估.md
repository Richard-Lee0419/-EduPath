# 01 · 现状差距与改造评估

> 结论先说：**这不是“把软件杯作品改个名字”能过的比赛。**
> 但也不需要推翻重写。原项目约 70% 的领域资产（课程语料、画像逻辑、资源结构、评测思路、前端设计语言）可以复用；真正要补的是 **AgentArts 平台层 + 工具协议层 + 比赛叙事层**。
> 改造原则：**原项目零代码改动**，在 `huawei-ict/` 子目录做旁路适配，单独分支维护。

---

## 1. 原项目现状（基线）

仓库：<https://github.com/Richard-Lee0419/-EduPath>（`main`，2026-10-10 更新）

### 1.1 架构

```text
Vue 3 / TypeScript 前端
        │ /api/*
        ▼
Spring Boot 业务服务（MySQL / 本地 H2）
        │ 内部 AI 请求、任务状态
        ▼
FastAPI / Pydantic AI 服务
  ├─ 画像提取
  ├─ 课程 RAG（local / Chroma）
  ├─ 多角色结构化生成（讲义/导图/题库/代码实验/流程图）
  ├─ 路径规划与重规划
  ├─ 辅导、测验、评估
  └─ SafetyAgent + 质量门禁
```

### 1.3 现有叙事的问题

原项目是“软件杯 A3 作品”，叙事重心是**功能完整度与工程实现**；华为 ICT 赛题 2 的重心是**平台使用深度 + 场景创新 + 商业价值**。同一套东西，换一个讲法不够，必须补平台证据。

## 2. 硬缺口（不补会直接不符合赛题）

| # | 缺口 | 严重度 | 说明 |
| --- | --- | --- | --- |
| G1 | 智能体不在 AgentArts 上 | **阻断** | 当前编排在 Python 进程内；赛题要求“基于 AgentArts 完成构建、编排与部署” |
| G2 | 知识库不在 AgentArts | **高** | 当前 Chroma/本地向量；平台知识库需单独上传、命中测试、引用 |
| G3 | 工具不是 MCP / 平台插件 | **高** | 当前是内部 HTTP API；平台无法自动发现与调用 |
| G4 | 没有平台内的评测记录 | **高** | 评分明确看“效果评估”；需要评测集、指标、失败样例 |
| G5 | Demo 不是“AgentArts 演示” | **高** | 现有前端是业务系统，评委看不到平台编排 |
| G6 | 材料是软件杯/UCD 风格 | **中高** | 信息表、PPT、视频都要重写叙事 |
| G7 | 没有华为云部署 | **中** | 至少要有发布/运行记录；决赛更强 |
| G8 | 没有平台版本/发布记录 | **中** | 需要提交版本号、发布截图、API 调用证据 |

### 2.1 一个必须说清楚的技术事实

AgentArts 的平台知识库**不对外提供检索 API**（官方 SDK 没有知识库模块；第三方知识库的方向是“你实现接口给平台调”，不是平台给你接口）。这意味着：

- **方案 A（推荐）**：把主流程做成 AgentArts 的**工作流/多智能体**，知识库挂在平台智能体上；MCP 工具负责业务动作。平台内闭环，证据最硬。
- **方案 B（备选）**：用 AgentArts SDK 把 Python Agent 部署成运行时（`/invocations`），知识检索走 MCP 工具调原项目 RAG；平台负责托管、网关、记忆、评测。
- **不要宣称**“高代码 Agent 直接调平台知识库”——目前做不到，答辩会被问穿。

本仓库同时给出 A 的配置与 B 的适配层，默认 Demo 用本地链路彩排。

## 3. 改造策略：旁路适配，不动原项目

```text
原项目（main，保持不动）
  ├─ frontend/            复用设计语言与业务流程
  ├─ backend-api/         保留业务 API
  └─ ai-agent-service/    保留 RAG / 生成 / 评估能力
            ▲
            │ 只读调用（HTTP）
            │
huawei-ict/（新增子目录，独立分支）
  ├─ bridge/              MCP 工具 + 本地编排 + 网关 + AgentArts 客户端
  ├─ web/                 比赛专用可视化 Demo
  ├─ agentarts/           提示词、工作流、知识库、评测集配置
  ├─ docs/                赛题解读、设计、联调、脚本
  ├─ submission/          信息表、PPT、提交清单
  └─ evidence/            截图、自检报告
```

### 3.1 三条可选轨道

| 轨道 | 做法 | 平台证据强度 | 复用度 | 工作量 | 建议 |
| --- | --- | --- | --- | --- | --- |
| **A. 平台工作流（推荐）** | AgentArts 工作流/多智能体 + 平台知识库 + MCP 工具 | ★★★★★ | 60% | 中 | 初赛主推 |
| B. SDK 高代码运行时 | Python Agent 用 AgentArts SDK 部署；MCP 调原 RAG | ★★★☆ | 85% | 中低 | 作为技术备选/加分 |
| C. 纯本地演示 | 本仓库 `fixture` 模式 | ★（不能单独提交） | 100% | 低 | 只用于彩排/录屏底稿 |

> 建议：**A 为主，B 作为“高代码扩展”一页放在 PPT 里**。不要把 B 说成 A。

### 3.2 为什么不全量重写

- 原项目的 RAG、质量门禁、SafetyAgent、路径重规划是真正花时间的地方，重写会引入回归。
- 比赛评审看的是“平台使用 + 场景价值”，不是代码行数。把既有能力包装成 MCP 工具，是更聪明的工程决策。
- 原项目要继续用于简历/其他投递，不能被比赛版本污染。

## 5. 改动“大不大”：分维度回答

| 维度 | 判断 | 理由 |
| --- | --- | --- |
| 叙事/定位 | **大** | 从“功能完整的学习平台”改为“AgentArts 上的课程学习智能体” |
| 平台架构 | **大** | 编排权从 Python 迁移到 AgentArts；这是赛题的核心 |
| 领域代码 | **中** | 既有 RAG/生成/评估保留，通过 MCP 暴露 |
| 前端 | **中** | 不复用整个业务前端，另做聚焦 Demo；设计语言复用 |
| 知识库 | **中** | 语料已清洗，主要是上传、元数据、命中测试 |
| 材料 | **大** | 信息表、PPT、视频全部重写 |
| 原项目风险 | **极低** | 旁路适配，零侵入 |

**一句话：叙事和平台层是大改，代码是中等改造，原项目本身不用改。**

## 8. 结论与建议

1. **可以参赛，且基础不差**：EduPath 的领域深度（课程 RAG、画像、质量门禁、路径重规划）比大多数“套壳聊天机器人”强。
2. **必须补平台证据**：至少完成“平台知识库 + 工作流 + MCP 工具 + 发布 + 评测”五件事，缺一不可。
3. **不要重写原项目**：用 `huawei-ict/` 旁路适配，原项目继续用于简历与其他投递。
4. **先做减法**：初赛 Demo 只讲“一个学生、一门课、一次完整学习任务”，不要巡览全部功能。
5. **时间估算**：有本仓库骨架的情况下，剩余 **5–8 人日** 可形成可提交版本；要打磨到决赛水平，再预留 **1–2 周**。
