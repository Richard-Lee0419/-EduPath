# 05 · 部署与联调指南

> 目标：三条链路都能跑通——
> ① 本地离线 Demo（评委/自己彩排）；② 接原项目 AI 服务（真 RAG/真生成）；③ 接 AgentArts 已发布端点（正式提交）。
> 原则：**先本地跑通，再上云；每一步都留截图/日志。**

---

## 1. 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Python | 3.11+ | 只用标准库，无需 pip install |
| 操作系统 | Windows / macOS / Linux | 已在本机 Windows 验证 |
| 浏览器 | Chrome / Edge / Safari 现代版本 | Demo 用 EventSource |
| 端口 | 8765（可改） | 不占用原项目 5173/8080/8000 |
| 云资源 | ECS 2C4G 起 / 或 CCE | 仅正式演示需要 |

---

## 2. 本地离线 Demo（3 分钟跑通）

```powershell
cd huawei-ict
python -m bridge.gateway --port 8765
```

打开 <http://127.0.0.1:8765/>，点击“运行演示”。

- 默认 `EDUPATH_BRIDGE_MODE=fixture`：不调用任何云服务，使用课程证据约束的演示数据。
- 页面右上角会显示“本地演示 · 未上云”，这是**故意**的：不能把彩排说成平台运行。
- 演示约 6.8 秒（UI 按步骤回放）；真实模型会慢一些。

### 2.1 录屏/截图模式

```text
http://127.0.0.1:8765/?demo=done               # 直接加载完成态
http://127.0.0.1:8765/?demo=done&full=1        # 展开轨迹与产物（截图用）
http://127.0.0.1:8765/?demo=done&full=1&tab=quiz
```

支持 `tab=lecture|mindmap|quiz|path`。

### 2.2 健康检查

```bash
curl http://127.0.0.1:8765/health
curl http://127.0.0.1:8765/runtime
```

`/runtime` 会明确返回 `mode`、`agentarts_configured`、`edupath_ai_configured`，方便排查“到底连没连上”。

## 3. 接原项目 AI 服务（真 RAG）

### 3.1 启动原项目 AI 服务

在**原项目**目录（不要改代码）：

```bash
cd ai-agent-service      # 旧版可能是 ai-service
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -e ".[dev]"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

确认：

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/runtime
```

### 3.2 让 bridge 指向它

```powershell
$env:EDUPATH_BRIDGE_MODE="edupath_ai"
$env:EDUPATH_AI_BASE_URL="http://127.0.0.1:8000"
python -m bridge.gateway --port 8765
```

此时工具返回的 `mode` 为 `edupath_ai_service`；如果某个端点失败，会回退 fixture 并带 `fallback_reason`，页面会提示。**不要把回退结果当真实模型结果。**

### 3.3 验证

```bash
curl -s http://127.0.0.1:8765/api/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"edupath_search_knowledge","arguments":{"query":"二叉树 中序","course_id":1,"top_k":3}}}'
```

检查 `mode` 与 `results[].source`。

> 原项目 AI 服务可能启用真实模型/Chroma；首次调用会慢，属正常。若要控成本，先只测 `/kb/search`。

## 4. 接 AgentArts（正式）

### 4.1 在平台完成四件事

1. 知识库：见 `docs/03`。
2. MCP 工具：见 `docs/04`。
3. 工作流：见 `docs/02` 的 12 节点。
4. 发布：提交版本 → 发布 API / Web 应用。

### 4.2 拿到端点

在 AgentArts“发布/API 调用”页面复制：

- 调用 URL（`AGENTARTS_ENDPOINT`）
- API Key（`AGENTARTS_API_KEY`）
- 应用/智能体 id（`AGENTARTS_APP_ID`，如需要）
- 协议类型（通用 JSON / OpenAI 兼容）

### 4.3 配置

```powershell
$env:EDUPATH_BRIDGE_MODE="agentarts"
$env:AGENTARTS_ENDPOINT="https://<agentarts-endpoint>/..."
$env:AGENTARTS_API_KEY="<your-key>"
$env:AGENTARTS_PROTOCOL="generic"      # 或 openai
$env:AGENTARTS_APP_ID="<optional>"
$env:AGENTARTS_MODEL="DeepSeek-V4-Flash"
python -m bridge.gateway --port 8765
```

打开页面，右上角应显示“AgentArts 已发布智能体”。运行后：

- 若端点返回 `output`/`answer`/`data.output`/`choices[0].message.content`，会附在任务结果的 `agentarts` 字段。
- 若调用失败，任务会带 `warning` 并回退本地链路；页面会提示。**正式录屏前必须确认没有 warning。**

### 4.4 协议适配

不同发布方式的请求体可能不同。`bridge/agentarts_client.py` 已支持：

| 协议 | 请求 | 响应读取 |
| --- | --- | --- |
| `generic` | `{"input":{"message":...,"context":...},"session_id":...}` | `output` / `answer` / `data.output` |
| `openai` | `{"model":...,"messages":[...]}` | `choices[0].message.content` |

如果平台要求其他字段，改 `_payload()` 与 `_normalise()` 两个函数即可；不要把端点写死在业务代码里。

## 5. 云端部署（ECS 方案）

### 5.1 资源

| 资源 | 规格 | 用途 |
| --- | --- | --- |
| ECS | 2 vCPU / 4 GB / Ubuntu 22.04 | 跑 bridge + Nginx |
| 弹性公网 IP | 按量/带宽 | 让 AgentArts 与评委访问 |
| 安全组 | 入方向 80/443，SSH 限 IP | 不暴露 8765 |
| 域名 + HTTPS | 可选但强烈建议 | AgentArts 回调/浏览器安全 |
| MaaS API Key | 平台申请 | 真实模型 |

### 5.2 部署步骤

```bash
# 1. 安装
sudo apt update && sudo apt install -y python3.11 nginx
# 2. 上传代码（git clone 或 scp）
git clone -b huawei-ict-2026 https://github.com/Richard-Lee0419/-EduPath.git
cd ./-EduPath/huawei-ict
# 3. 启动（systemd 示例）
sudo tee /etc/systemd/system/edupath-bridge.service > /dev/null <<'EOF'
[Unit]
Description=EduPath AgentArts Bridge
After=network.target
[Service]
WorkingDirectory=/opt/edupath/huawei-ict
Environment=EDUPATH_BRIDGE_MODE=agentarts
Environment=AGENTARTS_ENDPOINT=https://...
Environment=AGENTARTS_API_KEY=...
ExecStart=/usr/bin/python3 -m bridge.gateway --host 127.0.0.1 --port 8765
Restart=always
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now edupath-bridge
```

### 5.3 Nginx 反向代理

```nginx
server {
  listen 443 ssl http2;
  server_name demo.example.com;

  location / {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_buffering off;          # SSE 必须
    proxy_read_timeout 300s;
  }
}
```

> SSE 必须关闭 `proxy_buffering`，否则页面会“卡住到最后一起出现”。

### 5.4 验证

```bash
curl https://demo.example.com/health
curl https://demo.example.com/runtime
```

浏览器打开，跑一次完整流程；确认：

- 右上角显示“AgentArts 已发布智能体”。
- 轨迹 9 步都出现。
- 证据侧栏有来源。
- 质量/安全显示通过。
- 刷新页面后能从 `/api/agent/tasks/{id}` 读到任务（如果保留任务存储；当前是内存态，重启丢失是已知边界）。

## 7. 故障排查

| 现象 | 排查 | 处理 |
| --- | --- | --- |
| 页面 404 / CSS 不加载 | 是否在 `huawei-ict/` 下启动 | `cd huawei-ict` 再运行 |
| 运行按钮无反应 | 浏览器控制台 / `/health` | 看是否端口冲突；换端口 |
| 轨迹只有一步 | 旧版本 bug | 更新到当前代码；`traceStarted` 逻辑 |
| 证据为空 | `search_knowledge` 返回 | 查 `/runtime` 的 mode；fixture 下应有 5 条 |
| AgentArts warning | 端点/Key/协议 | 用 curl 直接打端点；看返回体字段 |
| 质量分 0 | 生成失败 | 看任务 `error`；检查资源是否有 `evidence_chunk_ids` |
| SSE 卡住 | Nginx 缓冲 | `proxy_buffering off`；心跳 |
| 端口被占用 | `netstat -ano | findstr 8765` | 换端口或结束进程 |

## 8. 成本与额度

| 项 | 估算 | 控制 |
| --- | --- | --- |
| 模型调用 | 单次 Demo 6–10 次 | 录制时用 fixture 彩排，正式跑 2–3 次 |
| 知识库 | 1 GB 内 | 108 篇文档很小 |
| ECS | 2C4G 按量 | 录制/评审期开机，平时关机 |
| 带宽 | 1–5 Mbps | Demo 页面 < 1 MB |
| 代金券 | 以组委会为准 | 不假设一定到账，保留本地方案 |
