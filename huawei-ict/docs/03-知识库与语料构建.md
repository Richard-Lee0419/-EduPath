# 03 · 知识库与语料构建

> 目标：让评委相信“内容不是模型编的”，并且换一门课可以复制。
> 主路径：**AgentArts 平台知识库**；备选：第三方知识库接口；补充：MCP 检索工具。

---

## 1. 语料资产

### 1.1 规模

| 课程 | 文档数 | 主要主题 |
| --- | ---: | --- |
| 数据结构与算法 | 60 | 复杂度、线性表、链表、栈队列、树、堆、哈希、排序、区间结构、图算法、网络流、动态规划、字符串 |
| 计算机组成原理 | 48 | 数制/补码、对齐端序、ALU/数据通路、ISA、流水线、存储层次、Cache、MMIO/DMA、特权级、安全与验证 |

> 切片数是约数，以平台实际入库为准；不要在不同材料里写不同的精确数字。

### 1.2 来源与许可证

| 上游 | 许可证 | 用途 |
| --- | --- | --- |
| cp-algorithms | CC BY-SA 4.0 | 算法主题 |
| OpenDSA | MIT | 数据结构教学 |

每条记录保留：固定 commit、原文链接、许可证链接、中文适配说明、上游原文节选。完整清单在原项目 `ai-agent-service/data/seed_corpus/open_source_manifest.json`。

### 1.3 质量门槛（原项目已执行）

- 不接收许可证为 `unknown` 的生产语料。
- 每条记录必须有 HTTPS 来源、40 位提交哈希、SPDX 风格许可证、适配声明。
- 每篇正文 ≥ 1,200 字符，包含学习目标、知识关联、推演案例、工程检查、自测结构。
- 中文导读必须包含概念、复杂度或实现边界，不能只有链接或原文堆砌。
- 推演案例覆盖率 100%。

## 2. 文档元数据（平台入库必填）

建议在平台知识库的文档/分段元数据中保留以下字段。即使平台只支持部分字段，也要在文件名/首行中冗余，保证可追溯。

| 字段 | 示例 | 用途 |
| --- | --- | --- |
| `course_id` | `1` | 课程隔离 |
| `course_code` | `data_structures_algorithms` | 稳定标识 |
| `knowledge_point_id` | `9345` | 知识点过滤 |
| `knowledge_point` | `二叉树遍历` | 展示/检索 |
| `title` | `前序、中序、后序与层序遍历` | 引用标题 |
| `source` | `OpenDSA / BinaryTreeTraversal.rst` | 来源 |
| `source_url` | `https://github.com/...` | 可核验 |
| `source_commit` | `f4e4afc...` | 版本固定 |
| `license` | `MIT` | 合规 |
| `attribution` | `Adapted from OpenDSA contributors` | 归属 |
| `difficulty` | `basic` | 难度匹配 |
| `curriculum_tier` | `course_core` | 课程层级 |
| `search_aliases` | `["二叉树遍历","前序","中序"]` | 提升召回 |
| `pedagogy_sections` | `["中文教学导读","学习目标",...]` | 结构感知 |

> 平台知识库若不支持自定义元数据过滤，至少保证 `course_id` 与 `knowledge_point` 进入分段正文或标题，检索时用查询词约束。

## 3. 构建流程（从原文到平台）

```text
授权原文
  → 解析（PDF/DOCX/PPTX/Markdown）
  → 清洗（去导航/页眉页脚/重复）
  → 结构感知分段（标题路径 + 约 500 字）
  → 元数据标注（课程/知识点/来源/许可证）
  → 质量检查（长度/结构/许可证/重复）
  → JSONL / Markdown 导出
  → AgentArts 知识库上传
  → 命中测试
  → 评测集回归
```

### 3.1 分段建议

| 参数 | 建议 | 理由 |
| --- | --- | --- |
| 分段方式 | 自动分段 + 标题层级 3 | 保留“章/节/小节”上下文 |
| 分段长度 | 约 500 字 | 与现有语义分段接近；太长稀释引用，太短丢上下文 |
| 重叠 | 50–80 字 | 避免跨段结论断裂 |
| 保留标题路径 | 是 | 引用时能显示“二叉树遍历 > 递归实现” |
| 过滤 | 去页眉页脚、目录、广告 | 减少噪声 |

### 3.2 上传前自检

- [ ] 文件名不含学生姓名、学号、教师私人信息。
- [ ] 每篇有 `source`、`license`、`attribution`。
- [ ] 同一知识点没有重复文档（用标题+哈希去重）。
- [ ] 课程 id 与知识点 id 与业务库一致。
- [ ] 抽样 5 篇，人工读一遍，确认中文导读不是机翻堆砌。

## 4. AgentArts 平台知识库配置

> 以下为建议路径，具体菜单以控制台实际版本为准。

### 4.1 创建

1. 进入 AgentArts 控制台 → 知识库 → 创建知识库。
2. 名称：`edupath-course-kb`。
3. 类型：平台知识库（默认创建）。
4. 向量模型：`pangu_embedding`；精排：`pangu_rerank`。
5. 分段：自动分段，标题层级 3，预计长度 500。
6. 容量：先 1 GB（演示足够）。

### 4.2 上传

1. 选择两门课的 Markdown/JSONL 导出文件。
2. 等待状态变为“已启用”。
3. 记录文档数、切片数、向量模型、创建时间。
4. 截图保存：知识库列表、文档列表、分段详情。

### 4.3 命中测试（必须做，不测等于没建）

| 查询 | 期望命中 | 判定 |
| --- | --- | --- |
| 二叉树前序、中序、后序有什么区别 | 二叉树遍历文档，分数 ≥ 0.7 | 强命中 |
| 递归遍历为什么可能栈溢出 | DFS/递归栈文档，分数 ≥ 0.6 | 强命中 |
| 二叉搜索树中序为什么有序 | BST 文档，分数 ≥ 0.6 | 强命中 |
| 红黑树删除的 5 种情况 | 语料未覆盖，分数 < 0.35 | **弱命中/拒答** |

> 第 4 条是“负例”，非常重要：证明系统不是“什么问题都敢答”。平台服务端可能不做阈值过滤，阈值要在工作流/应用侧卡。

### 4.4 引用与归属

- 打开“引用和归属”，让回答带来源。
- 生成节点提示词要求“每条结论后标注 `[E1]`，E1 必须在检索结果中”。
- 发布前校验引用 id 是否存在；不存在则降级为草稿。

## 5. 检索策略

### 5.1 查询构造

```text
query = 学生问题 + 知识点 + 资源类型意图
例： "递归总是绕晕 二叉树遍历 图解讲义 前序 中序 后序"
```

- 不要直接把整段学生自述丢给检索；先由主控抽取 `knowledge_point` 与 `intent`。
- 多知识点时拆成多次检索，再合并去重。
- 课程过滤必须带 `course_id`，防止“数据结构”查到“组成原理”。

### 5.2 阈值与降级

| 最高分 | 处理 |
| --- | --- |
| ≥ 0.65 | 正常生成，引用 3–5 条 |
| 0.35–0.65 | 生成但标注“证据较弱”，减少确定性表述 |
| < 0.35 | 不生成确定性结论；回复“现有资料未覆盖”，建议换知识点或问教师 |

### 5.3 引用格式

- 正文：`...适合复制或序列化 [E1]。`
- 证据侧栏：`E1 · 前序、中序、后序与层序遍历 · 0.94 · OpenDSA / MIT`
- 不要只写“根据资料”，要能点到 chunk。

## 6. 第三方知识库接口（备选）

如果不想把语料搬进平台，或想复用现有 Chroma，可以让 AgentArts 调你的检索服务。方向是**你实现接口给平台调**：

```http
GET  /knowledge-bases
POST /knowledge-bases/retrieve
```

`retrieve` 请求建议：

```json
{
  "knowledge_base_id": "edupath-chroma",
  "query": "二叉树 中序 递归栈",
  "top_k": 5,
  "filters": {"course_id": 1}
}
```

响应建议：

```json
{
  "results": [
    {
      "id": "E1",
      "title": "前序、中序、后序与层序遍历",
      "content": "...",
      "score": 0.94,
      "source": "OpenDSA / BinaryTreeTraversal.rst",
      "metadata": {"course_id": 1, "knowledge_point_id": 9345, "license": "MIT"}
    }
  ]
}
```

> 具体字段以华为云《第三方通用知识库接入规范》为准。好处是复用现有 RAG；坏处是要自己保证可用性、鉴权、限流和引用展示。

## 7. 版权、隐私与学术诚信

| 风险 | 做法 |
| --- | --- |
| 教材/课件版权 | 只使用有许可证的公开语料，或取得教师书面授权；不把受版权保护的教材全文上传 |
| 学生隐私 | 演示用脱敏画像（林同学/ stu-demo-001）；不接真实学号、姓名、成绩 |
| 教师隐私 | 班级数据聚合后使用；不上传含个人信息的名单 |
| 学术诚信 | 不生成可直接提交的作业答案；练习附解析；安全员拦截“代写/代考” |
| 许可证传染 | CC BY-SA 内容保留署名与相同方式共享；不要闭源打包出售语料本身 |
| 引用错误 | 发布前校验引用 id；弱证据拒答 |

## 8. 评测与维护

### 8.1 评测集

`agentarts/evaluation_set.jsonl` 24 条，知识库相关 8 条：

- 强命中 4 条：应引用正确文档。
- 弱命中 2 条：应标注证据弱/拒答。
- 跨课程 2 条：不应串课。

指标：`hit@5`、`citation_precision`（引用是否支持结论）、`refusal_accuracy`（该拒答时拒答）。

### 8.2 更新流程

1. 新增/修订文档 → 更新 manifest（来源/许可证/commit）。
2. 重新分段 → 本地检索回归。
3. 平台知识库增量上传 → 命中测试。
4. 跑评测集 → 记录版本与分数。
5. 更新 `docs/03` 的规模数字与截图。

> 不要把“文档数多”当质量。评审更关心“引用是否支持结论、弱证据是否拒答”。
