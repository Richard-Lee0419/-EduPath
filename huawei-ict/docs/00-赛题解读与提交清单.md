## 1. 一句话结论

这不是“再交一个软件作品”的比赛，而是**用 AgentArts 把一个真实场景做成可演示、可评测、可复制的智能体应用**的比赛。

- **硬门槛**：智能体必须在华为云 AgentArts 上完成构建、编排与部署；Demo 要能看出平台能力的使用。
- **得分重心**：创新性 60%，应用价值 40%。功能数量不是重点，“新场景 / 新交互 / 差异化 + 真实落地”才是。
- **对 EduPath 的含义**：原有业务与课程资产可以复用，但**不能只把原系统录屏交上去**；必须把“画像—检索—生成—评估—路径”的编排迁移到 AgentArts，并留下平台内构建与运行的证据。

## 2. 赛题原文结构化

### 2.1 应用领域

休闲娱乐、办公助手、行业应用、生活服务等不限，鼓励真实业务痛点与落地潜力。典型方向：

| 方向 | 官方举例 | EduPath 的归属 |
| --- | --- | --- |
| 行业赋能型 | 医疗、教育、金融、制造、农业 | **教育**（主归属） |
| 效率提升型 | 办公自动化、智能客服、数据分析、文档处理 | 教师备课/资源生产效率（次归属） |
| 创新探索型 | 多 Agent 协同、自主决策、MCP 工具调用、持续学习 | **多 Agent + MCP + 知识接入**（技术亮点） |
| 生活服务型 | 健康管理、出行规划、学习辅助、智能家居 | 学习辅助（可作为传播语境） |

> 建议报名表格“应用领域”写：**行业赋能型（教育）+ 创新探索型（多 Agent / MCP）**。不要四项都写，显得没有焦点。

### 2.2 任务要求（逐条翻译成验收条件）

| 官方要求 | 验收证据 | 我们的对应产物 |

### 2.3 评审规则拆解

#### 一、创新性（60%）

| 子项 | 评委实际在问 | 我们的回答（一句话） | 证据 |
| --- | --- | --- | --- |
| AI 应用场景创新（新场景或传统场景新突破） | 为什么是现在？为什么是这个场景？ | 把“课程证据 + 版本化画像 + 测验回流”做成可执行闭环，而不是通用答疑 | 画像 v3、证据引用、路径重规划 |
| 与行业现有方案形成差异化优势 | 和通用 AI 学习助手/题库/MOOC 有什么不同？ | 内容必须引用课程 chunk；画像与路径会因作答而变；过程可解释 | `docs/08` 对比表 |
| 智能体设计思路或交互方式创新 | 交互上有什么非 ChatBot 的东西？ | “学习任务卡 + Agent 协作轨迹 + 证据侧栏 + 产物工作台” | Demo 截图 |

> 60% 的创新性不要求“造一个新模型”。**把通用能力组合到别人没做透的场景，并把闭环做真**，就是创新。

#### 二、应用价值（40%）

| 子项 | 评委实际在问 | 我们的回答 | 证据 |
| --- | --- | --- | --- |
| 精准定位真实需求并解决对应问题 | 谁痛？痛在哪？ | 大班课无法个性化；学生不知道弱在哪；教师备课重复 | 用户故事、两门课、真实班级场景 |
| 具备商用落地潜力 | 谁付费？怎么交付？ | 高校课程包 / 院系 SaaS / 教师工作台；按课程复制 | `docs/08` 商业模式 |
| 可复制性与规模化应用前景 | 换一门课要重做多少？ | 只换语料、知识点元数据、评测集；工作流/工具/前端复用 | 两门课结构、知识库流水线 |
| Agent 架构设计合理、可行 | 会不会只是 Demo？ | 8 角色职责清晰、失败可回退、任务有状态、指标可测 | `docs/02`、自检报告 |

## 3. 初赛需要交什么

官方材料（赛题要求图）明确：

1. **作品信息收集表（Word）**——模板已给，必交。
2. **作品介绍 PPT / 设计文件 / 演示视频等相关文件（如有）**——建议全交，PPT 与 3 分钟视频是初赛最主要的“印象分”。
3. 信息表内需要呈现：
   - 作品简介与创意点
   - 团队介绍
   - Agent 设计方案（场景定义、编排思路、工作流架构、模型与资产选择）
   - 面向的行业问题 / 落地场景
   - 作品 Demo 视频展示（基于 AgentArts 构建与运行的完整流程）

> 结论：**信息表不是“登记表”，而是第一份评审材料**。技术方案介绍要能独立阅读，不能只写“详见 PPT”。

## 4. 官方补充问答（容易误读的三点）

| 问题 | 官方回答 | 对我们的影响 |
| --- | --- | --- |
| 必须使用多智能体吗？ | **不要求**。可选单智能体、工作流、多智能体协同或高代码开发 | 我们选“**主控 + 工作流 + 多角色**”，但答辩时不要说“平台强制多 Agent”；强调是场景需要 |
| 可以集成到鸿蒙 APP/Web 吗？ | 可以，按应用需求集成到鸿蒙 APP、Web 应用等 | Demo 用 Web 最稳；鸿蒙可作为后续规划，不要作为已交付 |
| 必须结合硬件吗？ | **不要求**。可纯软件，也可结合物联网/传感器 | 我们纯软件，不需要为“创新”硬加硬件 |

> 答辩口径：**“我们不是为 multi-agent 而 multi-agent。画像、检索、生成、评估的职责和失败边界不同，拆开才能独立重试、独立评测、独立替换模型。”**

## 6. 建议的执行节奏（以 4 周为例）

| 周 | 目标 | 交付 |
| --- | --- | --- |
| W1 | 账号、知识库、3 个核心智能体跑通 | 知识库命中测试截图、单智能体试运行 |
| W2 | 工作流 + MCP 工具 + 质量/安全门禁 | 工作流版本、工具调用日志 |
| W3 | Demo 页面接真实端点、录制视频 | 3.5 分钟视频、5 张截图 |

> 如果距离截止不足 2 周：优先保“**平台内可运行 + 3 分钟视频 + 信息表**”，PPT 可以简化；不要为了多做两个 Agent 牺牲主流程稳定性。
