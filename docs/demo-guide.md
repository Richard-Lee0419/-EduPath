## 自动复现与录制

先按 README 启动隔离 H2 Java、无密钥 AI 和 Vite，默认端口 8080、8000、5173。然后：

```bash
cd frontend
npm ci
npx playwright install chromium
npm run test:e2e
npm run test:e2e:record
```

两项 E2E 测试直接操作真实页面，不 mock HTTP：学生画像→资源→路径→测验→更新及刷新读取；教师被拒绝的资料上传后显示失败，刷新后仍显示失败，最后删除测试资料。学生测试每次注册新合成账号，教师使用本地 seed 账号；不要连接生产数据库。

`test:e2e:record` 只录制学生用例，在关键结果停留并截图；仅在所有断言通过后把视频、三张截图和 [录制记录](evidence/browser-recording.json) 复制至 `docs/evidence/`。原始 trace、页面登录状态和全部报告留在忽略的 `frontend/test-results/`、`playwright-report/`。自定义端口可设置 `EDUPATH_BROWSER_URL`、`EDUPATH_BACKEND_URL`、`EDUPATH_AI_URL`；URL 必须为本机地址。浏览器测试不会启动依赖服务。

Linux/CI 可设置 `EDUPATH_BROWSER_TESTS=true` 后运行 `bash scripts/ci-learning-flow.sh`，启动器同时管理 H2、AI、Vite，结束时关闭自己启动的进程。首次运行需要 `npx playwright install --with-deps chromium`。

## 演示准备

1. 使用本地实例，学生账号 `demo / 123456`，教师账号 `teacher / 123456`。这些是共享演示数据；不要录入真实个人信息。
2. 打开 AI `/runtime`，记录是否配置模型和 embedding；输出也需核对 `generation_mode`、`model_runtime`。
3. 选择课程一《数据结构与算法》，主题“二叉树递归遍历”或“深度优先搜索”。先查看已有画像和路径版本，便于解释之后的变化。
4. 记录演示日期、Git 提交、运行环境。若配置真实模型，先确认调用权限与费用，并避免录出密钥。
5. 不把教师“准备演示数据”的固定样例当作刚刚真实生成或真实学生使用记录。

## 2–3分钟学生主流程

| 时间 | 操作 | 应展示的证据 |
| --- | --- | --- |
| 0:00–0:30 | 学习画像输入：“我能写循环，但不理解递归调用栈，每天可学30分钟，希望掌握二叉树遍历。” | 画像具体字段与版本；解释哪些来自输入，哪些尚未知 |
| 0:30–1:10 | 选择课程、主题与1–2类资源，开始生成 | 任务 ID、状态/进度、结果来源模式；保留真实等待或注明加速 |
| 1:10–1:40 | 打开讲义/图解和证据 | 一段实际内容、对应 chunk/source；DFS 可展示访问顺序与栈 |
| 1:40–2:20 | 生成最多3道小测，作答并提交 | 实际题目、答案反馈与评估，不只展示预制报告 |
| 2:20–3:00 | 查看画像与学习路径 | 提交前后版本与调整理由；这是机制反馈，不能称学习能力已经提高 |

确定性模式的演示仍能证明业务流程和展示能力，但必须标注“无密钥开发模式”。真实模型演示只证明该次调用成功，不能据此声称长期可靠性或学习效果。

## 失败情况如何演示

可在本地单独展示一次取消或缺少证据的请求：终态清楚、错误可解释、资源未被当作成功发布。若任务已经完成再点击取消，不能视为验证取消中的竞态。不要在共享线上实例执行失败注入。

页面刷新后重新连接原任务是客户端重连；服务重启后的失败及重新执行是恢复处理，二者均不是断点续跑。

## API 验证与浏览器证据的区别

本地跨服务 API 验证通过真实 HTTP 连接 Java 与 Python，检查登录、画像、生成资源及证据、路径、测验、评估和状态变化；其模式与执行结果以验证记录为准。新增 Chromium 测试补充按钮、页面渲染和刷新读取验证，并发现、修复了小测前端误读异步响应的问题。桌面流程通过不能代表全部资源组件或移动端交互均已验证。

`scripts/demo-smoke.ps1` 会调用演示准备接口并写入固定演示数据，其检查属于“演示样例可读取”，不能作为新资源生成或学习效果实验。旧彩排脚本提到的前端“演示模式”入口已被移除，录制以当前页面为准。

## 另行录制的最低要求

另行制作真实模型或线上视频时，把可访问链接及以下信息补到本页和 README：

- 日期、提交版本、课程/主题、运行模式与模型/embedding（不附密钥）。
- 实际覆盖的步骤、是否剪辑等待时间。
- 已知失败或未展示步骤；若来自线上实例，注明不能保证与仓库一致。

这是一份工程演示，不需要正式用户研究、宣传指标或大量功能巡览。先展示一次完整学习任务即可。
