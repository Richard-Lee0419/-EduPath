# Cache 地址拆分与错因诊断

EDUPATH-CACHE-ADDR-V1 · 《计算机组成原理》· EduPath 团队自编 · v1

## 地址字段计算

EDUPATH-CACHE-ADDR-V1。按字节寻址，地址宽度为 A 位，Cache 数据容量为 C 字节（只计数据），块大小为 B 字节，每组有 W 个数据块。总块数为 C ÷ B，组数 S 为 C ÷ (B × W)。B 与 S 为 2 的幂时，Offset = log₂(B)，Index = log₂(S)，Tag = A − Index − Offset。直接映射的 W = 1，全相联只有一组，Index = 0。题干没有给相联度或映射方式时，通常无法唯一确定组数、Index 和 Tag。

## 四路组相联算例

EDUPATH-CACHE-ADDR-V1。32 位按字节寻址，容量 4 KiB = 4096 B，块 16 B，四路组相联。256 个总块分成 64 组，组索引 6 位。块内 16 个位置编号为 0–15，偏移 4 位。剩余标签 22 位。按 Tag / Index / Offset 顺序为 22 / 6 / 4。若改用直接映射，256 个总块分成 256 组，三个字段为 20 / 8 / 4。若改用二路相联，128 组，三个字段为 21 / 7 / 4。

## 两种错因与补救复测

EDUPATH-CACHE-ADDR-V1。组索引写成 8 位且偏移写对时，先检查是否把总块数当成组数。四路要先用 256 ÷ 4 得到 64 组，再求 6 位 Index。补救题可以改为二路相联，要求先写总块数与组数，再写 Index 位数。

EDUPATH-CACHE-ADDR-V1。偏移写成 5 位且组索引写对时，先检查是否把 16 个字节位置当成需要表达从 0 到 16 的范围。块内字节位置只有 0 到 15，4 位即可。补救题可以改为 32 B 块，要求写出最后一个字节的偏移和所需位数。

## 复算方法

EDUPATH-CACHE-ADDR-V1。已知字节地址 x 时，整数除法得到块号 q = x ÷ B，余数是块内 Offset。再将块号除以组数 S，余数是 Index，商是 Tag 的数值。这一方法可用来复查按位切分的结果，尤其适合检查最后一个块内位置和下一个块的开头。
